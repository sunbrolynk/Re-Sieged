# AI Disclosure

> **Status: draft.** To be finalized by the project lead.

Re-Sieged is developed with substantial help from AI tools. We state this
openly because it affects how contributors, players and rights holders should
judge the project's work, especially its clean-room claims.

## Tools used

| Tool | Used for |
| --- | --- |
| Anthropic Claude (via Claude Code) | Research analysis, documentation, planning, analysis scripts |
| OpenAI Codex | Static archaeology (WSL), native Windows environment setup and runtime observation |

We will update this list whenever the set of tools changes.

## What AI does and does not do here

- AI agents draft research notes, scripts, and documentation.
- **A human project lead** directs the work, reviews it, and makes every final
  decision: phase gates, architecture decisions, licensing, and merges to `main`.
- AI output is **not trusted by default**. It goes through the same evidence
  review as any other contribution ([research method](docs/research/README.md)).

## Clean-room safeguards specific to AI

AI models are trained on large public datasets, and we cannot rule out that
those datasets contained proprietary or leaked material. To keep that from
reaching Re-Sieged:

1. **Model "knowledge" is not evidence.** A claim about how DS2 works internally
   is accepted only when it is backed by observation of a legitimately owned
   copy, openly licensed tools, or public documentation, and has an evidence
   record. "The model said so" is never a source.
2. Agents are instructed never to use, reproduce, or seek leaked source code.
3. Code suggested by AI that looks like it reproduces a specific external
   project must be traced and recorded in the provenance log, or rejected.
4. No game assets are generated by, or fed into, AI tools for redistribution.

## Attribution

Commits written with AI assistance carry a `Co-Authored-By:` trailer that names
the tool. Pull requests created by an AI agent say so in their description.
